## Ways to use models here

1. **Stay in this session.** Work on the model you are running. Right for small, reversible changes and for work that already has its context here.
2. **A subagent of your own harness.** <Name the harness's subagent tool and the models it accepts.> Right for wide reads, independent work that can run in parallel, and keeping this session's context small.

## Before you spawn

- Recheck only what you are about to use: the CLI is still on `PATH`, the Orca variables are still set, the model id is in `inventory.md`. If an id is missing, use another id that is in `inventory.md`. Never guess one.
- Remaining usage cannot be read here. If a start fails on a limit, run that seat on another agent for this run, say so in the reply, and change nothing in this skill.
- Say in the reply which model you chose and why, in one line.

## When a task does not match this skill

Decide which kind of mismatch it is.

- **A stable fact is wrong** (a flag a product refuses, a model that is gone). Ask the user. On yes, fix `inventory.md` or the file in `references/`, and append a line to `log.md` with the date, the product version, and what changed.
- **A preference no longer fits.** Ask the user. On yes, edit the sentence under `## Preferences` or add a branch to it, and append a line to `log.md`.
- **A transient state** (a limit, no network). Substitute for this run, say so in the reply, and change nothing.

Edit only files in this directory, and only after the user agrees.
